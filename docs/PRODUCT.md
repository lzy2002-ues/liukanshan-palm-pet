# 刘看山 AI 掌心陪伴萌宠 V0.1

> 状态：**历史 V0.1 基线，2026-11-19**。正式交付与开发以 `docs/PRD-V1.0.md` 为准；本文件保留为早期方向记录，不替换或改写现有 `docs/product-v1.md` 中的桌面 App 方案。

## 1. 一句话与价值

刘看山是一只住在用户掌心里的 AI 陪伴萌宠：用户可以随时长按倾诉，它会理解情绪、记住用户说过的重要烦恼；某一天，它会随机带来其他人相似的匿名经历。若用户明确同意把烦恼化为匿名提问，随机摇到该问题的人可以写下回答，再由刘看山带回给提问者。

产品要实现的不是“聊天次数”，而是一个安全、有边界的陪伴循环：

```text
掌心相遇 → 私密倾诉 → 被理解与记住
                         ├→ 某日随机带回相似匿名经历 / 知乎经验
                         └→ 用户编辑并确认 → 匿名提问 → 他人摇到并回答 → 回答带回 / 刘看山来信
```

## 2. 产品原则

1. **陪伴优先。** 刘看山先接住用户的感受，再提供建议、内容或互动；不把用户导向任务打卡或社交曝光。
2. **私密默认。** 私人对话、转写和记忆绝不自动公开；任何匿名提问都必须由用户编辑并明确确认发布。
3. **记忆有用且可控。** AI 只提炼有助于未来陪伴的最小必要记忆；用户可查看、编辑、删除或关闭记忆。
4. **摇一摇保留偶遇。** 奇遇不是推荐流或关注关系；用户发布的问题由其他用户摇一摇随机遇见，私密记忆则在未来被随机带回一则相似匿名经历。
5. **AI 有明确职责。** AI 仅用于语音转写、情绪理解、记忆提炼、回应生成和知乎内容关联推荐；不替用户公开、不冒充真人、也不作医疗或心理诊断。
6. **硬件轻交互。** V0.1 硬件通过屏幕文字、表情、动画和简单按键反馈传递陪伴，不做语音播报。

## 3. 用户与首次体验

面向希望有一个随手可触、又不必承受社交负担的陪伴对象的用户。典型时刻是用户感到烦闷、犹豫、孤单或想分享一件小事时，拿起刘看山并长按说话。

首次体验应在几分钟内让用户感到三件事：

1. 刘看山会以表情和短文字回应触摸、按键或摇晃，像一个有状态的掌心伙伴。
2. 长按说出一句心事后，用户能看到可检查的文字、得到贴合语气的回应，并理解这段内容默认只属于自己。
3. 用户知道这份烦恼可以只留给刘看山；未来会随机收到一则相似经历。若愿意，也能把内容改写成匿名问题，确认后交给摇一摇遇见它的人回答。

## 4. V0.1 核心闭环

### 4.1 日常陪伴

- 硬件显示刘看山的基础待机、开心、关心、思考、收到来信等表情和动画。
- 支持基础按键/触摸互动与短文字反馈；互动可形成当日轻量状态，但不做复杂养成数值、等级或任务压力。
- 手机/Web 配套端承载完整文字阅读、编辑、记忆管理、匿名发布确认和奇遇详情；硬件是随身入口与情绪载体。

### 4.2 长按语音倾诉与情绪记忆

1. 用户长按录音，松开后获得语音转写文字；V0.1 可使用真实或清楚标识的模拟 ASR。
2. 系统基于转写理解情绪倾向、主题和需要的陪伴方式，刘看山以文字、表情和动画回应。
3. 系统从对话中生成简短的私密记忆候选，例如“最近在为换工作感到不安”；它只用于后续陪伴和内容关联。
4. 用户可在配套端查看、修改、删除记忆，或关闭后续记忆；删除后不再用于生成关怀或推荐。
5. 保持私密不意味着这段烦恼被遗忘：在未来合适的一天，刘看山可以随机从已授权、已匿名的相似经历中带回一则给用户；这不会公开用户自己的原话。

**拟定的默认数据处理：** 原始音频仅为完成本次转写所必需的短暂处理，不作为长期记忆；转写、情绪理解结果和已保存记忆默认私密。具体保留时长、处理位置与账户同步策略在技术设计前确认。

### 4.3 匿名提问信（可选）

- 用户可从一段私密倾诉选择“转成匿名问题”；系统生成草稿，但不能直接发布。
- 用户在配套端编辑标题与正文，检查并删除可识别自己的信息后，点击确认发布。
- 发布后问题进入产品自己的“奇遇池”，不附带昵称、联系方式、原始音频、完整对话、精确时间或其他可识别资料。
- 用户可撤回仍在池中的问题；他人针对问题写下的回答会保留在提问者自己的收件盒中。V0.1 不提供公开评论区、私聊、关注、好友、排行榜或关系链。

### 4.4 情绪奇遇与知识奇遇

**相似经历回访（私密用户）**

- 刘看山根据用户私密记忆的主题，在未来不预告的合适时机，随机带回一则其他用户自愿分享并已匿名化的相似经历。
- 这是一份“有人也这样走过”的陪伴材料，不是对用户的公开画像、关注关系或内容推荐流；不展示对方身份，也不允许用户据此联系对方。
- 用户可跳过、隐藏该经历，或关闭此类回访；被跳过/隐藏的内容不应原样反复推送。

**问题奇遇（公开提问后）**

- 用户发布匿名问题后，其他用户摇一摇会随机遇见该问题；随机性是首要体验，不按熟人、热度或付费排序。
- 遇见者可以写下自己的回答或经验；发送后不建立实时对话，也不暴露双方身份。
- 提问者收到回答后，刘看山将回答带回收件盒，并触发一封温柔、简短的“来信”；来信不替代或改写对方的原话。

**知识奇遇**

- 刘看山可根据用户私密记忆中的主题，在合适时机带来一条相关知乎经验内容；用户无需公开自己的烦恼。
- 仅可使用赛事或平台明确授权的知乎官方能力。实际权限未确认前，内容必须标为“演示内容”或“暂不可用”，不得抓取 Cookie、模拟登录或使用未授权数据。
- 内容发现以启发和陪伴为目的，提供来源和外跳；V0.1 不构建复杂推荐流。

### 4.5 刘看山来信与主动关怀

- 触发条件包括：用户收到匿名问题的回答、某条私密记忆在合适的时间被带回相似经历，或出现可解释的相关知乎经验。
- 来信以设备屏幕短句、表情/动画和配套端详情呈现，不使用硬件语音播报。
- 主动关怀必须可被用户关闭、静音或删除；每次来信应能说明它基于“你保存过的某件事”或“你订阅/浏览过的主题”，不暗示不存在的事实。

## 5. MVP 范围

### 必须完成

- 基础萌宠动画、屏幕短文字、按键互动和摇一摇反馈。
- 长按语音 → 可见文字 → 情绪回应的演示闭环（真实或明确标识的模拟 ASR）。
- 简化的私密记忆创建、查看与删除。
- “不公开”与“转为匿名提问”的明确分支；匿名问题须编辑和二次确认后才能发布。
- 已发布的问题可被其他用户摇一摇随机遇见、写下回答，并将回答带回给提问者。
- 对不公开的用户，演示一次基于私密记忆随机带回的相似匿名经历，或相关知乎内容发现。
- 所有知乎内容使用官方授权能力，或清楚标识为演示/不可用。

### 暂不做

- 复杂养成、等级、货币、抽奖或连续打卡机制。
- 实时语音聊天、硬件语音播报、开放陌生人聊天、评论广场、关注关系和社交图谱。
- 复杂推荐系统、未经授权的知乎个人数据读取、Cookie 抓取、模拟登录或爬虫。
- 医疗/心理诊断、危机干预承诺或替代专业支持。
- V0.1 之外的多设备同步、生产级硬件量产、支付与商业化设计。

## 6. 关键状态与数据边界

为避免“只生成随机文案”，下列对象必须有可追溯状态、来源和用户控制项：

| 对象 | 最小状态 / 字段 | 边界 |
| --- | --- | --- |
| 倾诉片段 | 转写文本、创建时间、情绪/主题、处理状态 | 默认私密；原始音频不作长期记忆 |
| 私密记忆 | 摘要、主题、来源片段、保存/删除状态、最后使用时间 | 可查看、编辑、删除、停用 |
| 匿名提问 | 草稿、待用户确认、已发布、已撤回、过期 | 未确认不得进入奇遇池；不携带身份线索 |
| 相似经历回访 | 私密记忆主题、匿名经历 ID、带回/跳过/隐藏状态 | 不公开用户原话；无身份互见、可关闭 |
| 问题奇遇投递 | 问题 ID、随机匹配记录、回答内容、投递状态 | 回答只带回提问者；无实时互聊、无身份互见 |
| 来信 | 触发原因、内容、展示/已读/已关闭状态 | 用户可关闭主动触达 |
| 知乎内容 | 官方/演示来源、授权状态、主题、外跳链接 | 未授权不请求、不存储、不伪装为真实数据 |

## 7. 隐私、安全与内容治理

- 发布前提供醒目的匿名检查与编辑机会；系统应提示用户移除姓名、联系方式、地址、单位等身份线索，但最终发布权只在用户手中。
- 私密对话与记忆不能被匿名池、其他用户或公开页面读取；“匿名”不等于可公开全部原文。
- 相似经历、匿名提问和回答均须具备基础内容审核、举报、撤回/下架和频率限制能力。具体审核策略与运营归属待确认后补充。
- 当表达涉及可能的自伤、自杀或迫在眉睫的人身危险时，刘看山应以关怀、鼓励联系可信赖的人或当地紧急/专业支持为主；不得假称提供专业医疗判断，也不得把该内容自动投入奇遇池。
- 模型、ASR、授权密钥和服务端凭据只能放在服务端环境变量；客户端与硬件不保存这些密钥。

## 8. 成功标准

在一次可控演示中，用户能完成：拿起刘看山并互动 → 长按倾诉 → 看见转写和贴合的回应 → 选择保持私密或编辑确认匿名发布。保持私密时，用户会在之后随机收到一则相似匿名经历；发布问题时，另一位用户可摇一摇遇见问题、留下回答，提问者能收到回答与对应来信。两条路径都不暴露任何一方身份。

## 9. 待确认的实现前提（不阻塞本产品基线）

1. 硬件形态、屏幕尺寸、输入/传感器能力、联网方式及其与手机/Web 配套端的连接协议。
2. ASR、模型和长期记忆的部署位置，及原始音频、转写与记忆的准确保留/删除策略。
3. 赛事/平台提供的知乎官方能力、可用字段、OAuth 范围、限流与内容展示规则。
4. 匿名池的审核能力、举报处理、相似经历/问题/回答的生命周期和运营责任。
5. 主动关怀的触达渠道、默认频率、免打扰窗口与通知授权。
